# TAIS recorder on Lightsail

Run one service per input queue. A single subscription can deliver any number of facilities. The recorder reads the source from each message and has no facility list. The repository-level config.yaml lists deployment facilities and defines the recording window. Use a separate subscribed queue if REDS must continue receiving the same feed.

1. Build with Java 21+ and Maven using `mvn -f server/tais/pom.xml package`. Install the shaded `target/stars-tais-1.0-SNAPSHOT.jar` as `/opt/stars/tais.jar` on Linux. Install Java 21+ and AWS CLI v2 with support for conditional PutObject and SHA-256 checksums. The service must find `aws` on PATH.
2. Run `cmake -DSTACK=stars-tais -P server/tais/deploy/bucket.cmake` with the target AWS region configured and use the ArchiveBucket output. Run it again after changing retention_days in config.yaml. The bucket expires objects under `tais/` based on that setting. Lifecycle removal is asynchronous. Use a separate deployment identity to manage the bucket. The runner needs `s3:PutObject` and `s3:GetObject` on the bucket's `tais/*` objects.
3. Create a root-owned, mode-0600 `/etc/stars/tais.env` with `TAIS_JMS_URL`, `TAIS_VPN`, `SCDS_USERNAME`, `SCDS_PASSWORD`, `TAIS_QUEUE`, `TAIS_BUCKET` and `AWS_REGION`. Provide AWS credentials accessible to the service through the AWS CLI credential chain. Install the unit in `/etc/systemd/system/tais.service`, then run `systemctl daemon-reload` and `systemctl enable --now tais.service`.
4. Put `/var/lib/stars-tais` on persistent storage. Size it for uncompressed ingress during the longest S3 outage you need to tolerate. Monitor free space, the oldest .ready file, broker backlog, and `journalctl -u tais`. The 512 MiB JVM heap and 1 GiB service limit leave headroom on a 4 GB instance. Measure peak traffic on the target instance before choosing how many queues to run there.

Five-minute UTC windows use recorder receipt time. Each object is a zstd-compressed JSON-lines segment under `tais/v1/FACILITY/YYYY/MM/DD/HH/HHmm-UUID.jsonl.zst`. A restart or 64 MiB journal rollover can produce multiple segments in one window. Group all matching parts for playback. Each line stores the original text or base64 bytes, JMS ID and timestamp, redelivery flag, XML root, facility, receipt time, and writer-scoped sequence. Replay in receipt order and use sequence within a writer to resolve ties. JMS delivery is at least once. Consumers can recognize redelivery by queue and JMS ID when available.

Unroutable deliveries are archived under `unknown`. A delivery above the REDS 10 MiB limit or an unsupported JMS body stops ingestion before acknowledgement and requires operator attention. Ordinary malformed XML remains in the archive. Local durable writes precede JMS acknowledgement, so a permanent loss of the spool volume before upload can lose acknowledged data. The uploader checks S3's SHA-256 before freeing a segment. Service restart recovers complete journal lines and retries using the original S3 key.

### Reading recordings in the desktop app

Set `TAIS_BUCKET` to the ArchiveBucket output and launch STARS with AWS CLI v2 on PATH. The CLI uses the normal AWS credential chain, including `AWS_PROFILE` and `AWS_REGION`. Give the playback identity `s3:ListBucket` for the `tais/v1/*` prefixes and `s3:GetObject` for objects under those prefixes. The bucket stays private.

For offline playback, set `STARS_TAIS_DIR` to a local directory containing the same `tais/v1/...` tree. This takes precedence over S3. With neither source configured the app continues to support weather-only playback.

`net/tais.h` exposes a per-pane cache for the source TRACON. On start or seek it prepares three minutes ahead using whole five-minute recorder windows. The cache refreshes listings for late uploads, reuses immutable parts, and retains the previous window for ten seconds after crossing a boundary. Read a half-open interval with `between(fromNs, untilNs)` on the owning thread. A missing result means the interval is not cached. A successful empty result is an archive gap. Deliveries retain their JMS metadata and decoded XML or binary bytes; redeliveries are preserved. Initial transport readiness includes both TAIS and weather, with the existing 60-second timeout.

To check a deployed bucket or a local archive independently of the radar, build `cmake --build build --target taischeck`, then run `build/net/taischeck N90 2026-11-20T23:59:00Z` with a UTC time in the recording. To exercise signed requests and paginated listings offline, run `python3 net/tests/s3.py build/net/taischeck` with AWS CLI v2 and zstd installed.
